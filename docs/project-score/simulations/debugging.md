# Debugging Simulations

Use the same pattern every time: symptom, likely cause, files, process, expected fix, interview explanation.

| Scenario                                 | Symptom                                        | Likely cause                                  | Files to inspect                                         | Debugging process                            | Expected fix                                   | Interview explanation                                                      |
| ---------------------------------------- | ---------------------------------------------- | --------------------------------------------- | -------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------- |
| Missing Clerk token                      | 401 `AUTHENTICATION_REQUIRED`                  | No `Authorization` header                     | `apiClient.ts`, `auth.middleware.ts`                     | Check Network headers and `ApiAuthProvider`  | Ensure signed in and token provider is mounted | Backend requires Bearer token for protected APIs.                          |
| Invalid Clerk session                    | 401 `INVALID_AUTH_TOKEN`                       | Bad/expired token                             | `auth.middleware.ts`, Clerk setup                        | Reproduce with bad token, check Clerk config | Re-authenticate or fix Clerk env               | Identity verification failed before business logic.                        |
| Internal user not found                  | Protected APIs fail after valid Clerk identity | Clerk user has no `User` row                  | `auth.service.ts`, `auth.repository.ts`, onboarding docs | Compare Clerk user ID with DB user           | Complete onboarding or seed user               | Clerk identity is not enough for normal app access.                        |
| Wrong clinic context                     | 403 `CLINIC_ACCESS_DENIED`                     | Route `clinicId` differs from `User.clinicId` | `access.service.ts`, `ActiveClinicProvider.tsx`          | Check active clinic ID and request URL       | Use correct clinic or fix user mapping         | Backend prevents cross-clinic access.                                      |
| Forbidden role                           | 403 `ADMIN_REQUIRED`                           | Staff calling Admin-only route                | `clinic.routes.ts`, `access.service.ts`                  | Check user role and route middleware         | Use Admin account or remove UI link            | Role checks are backend authority.                                         |
| Invalid UUID                             | 400 `VALIDATION_ERROR`                         | Param/body fails Zod                          | `*.validation.ts`, `validateRequest.ts`                  | Check response details field                 | Send valid UUID                                | Runtime validation rejects malformed input.                                |
| Malformed JSON                           | 400 `MALFORMED_JSON`                           | Invalid request body syntax                   | `errorHandler.ts`, Express JSON middleware               | Send malformed body                          | Fix JSON serialization                         | Central error handler maps parse errors safely.                            |
| Zod failure                              | 400 field errors                               | Missing/invalid body/query                    | `validateRequest.ts`, feature schema                     | Inspect `error.details`                      | Fix payload or UI mapping                      | Backend validation is authoritative.                                       |
| Appointment conflict                     | 409 `APPOINTMENT_SLOT_CONFLICT`                | Same doctor/time active appointment           | `appointment.service.ts`, repository, migration          | Check existing active appointments           | Pick another slot                              | Exact slot conflict is protected.                                          |
| Duplicate relationship                   | 409 `UNIQUE_CONSTRAINT_FAILED` or domain error | Duplicate doctor/patient clinic link          | `schema.prisma`, doctor/patient repositories             | Check unique constraints                     | Reuse existing link or handle conflict         | DB constraints backstop service rules.                                     |
| Queue position/reorder conflict          | 409 `QUEUE_REORDER_CONFLICT`                   | Queue changed during reorder                  | `queue.service.ts`, `queue.repository.ts`                | Refresh queue, inspect active set            | Retry after refresh                            | Transaction detects stale reorder request.                                 |
| Failed transaction                       | Partial workflow absent after error            | One step threw inside transaction             | appointment/auth/queue repositories                      | Check logs and resulting rows                | Fix failing step and retry                     | Transaction should prevent partial commit.                                 |
| Prisma unique error                      | 409 generic unique error                       | DB unique constraint hit                      | `errorHandler.ts`, schema/migrations                     | Inspect Prisma error code                    | Add domain-specific mapping if needed          | Known Prisma errors are mapped centrally.                                  |
| Prisma not found                         | 404 `RECORD_NOT_FOUND`                         | Update/delete target missing                  | `errorHandler.ts`, repository                            | Reproduce with missing ID                    | Return domain-specific 404 where needed        | Avoid leaking DB internals.                                                |
| CORS failure                             | Browser blocks request                         | Origin not in allowed client origins          | `app.ts`, `env.ts`, deployment env                       | Check browser console and env vars           | Set `CLIENT_URL`/`LOCAL_CLIENT_URL`            | CORS protects browser cross-origin access.                                 |
| Wrong frontend API URL                   | `API_BASE_URL_INVALID` or network error        | `VITE_API_BASE_URL` missing/not `/api`        | `apiClient.ts`, `apps/web/.env.example`                  | Check env and built config                   | Set full backend `/api` URL                    | Frontend config must point to API base.                                    |
| Missing env variable                     | Server crashes on startup                      | Required env absent                           | `env.ts`, `.env.example`                                 | Read startup error                           | Set `DATABASE_URL`/`CLERK_SECRET_KEY`          | Fail fast prevents running with unsafe config.                             |
| Production frontend points wrong backend | UI loads but API fails                         | Wrong `VITE_API_BASE_URL` at build/deploy     | `apiClient.ts`, deployment docs                          | Check Network URL                            | Redeploy with correct env                      | Vite env is baked into frontend build.                                     |
| Stale UI data                            | Mutation succeeded but list unchanged          | Missing refetch/state update                  | feature page handlers                                    | Inspect mutation success path                | Refetch or merge response                      | UI state must reconcile after backend mutation.                            |
| Invalid status transition                | Unexpected status reversal allowed             | Strict transition graph not implemented       | `appointment.repository.ts`, `queue.service.ts`          | Compare intended lifecycle vs code           | Future strict transition issue                 | Be honest: final states are protected, broad non-final transitions remain. |
