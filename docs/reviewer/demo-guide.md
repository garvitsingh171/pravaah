# Reviewer Demo Guide

This is the reviewer/interview demo script. Use Admin for the full path and Staff for an operations-only path.

## Prerequisites

| Item               | Requirement                                                                                                                                                             |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Environment        | Local, preview, or verified demo production environment.                                                                                                                |
| Role               | Admin for onboarding/settings/sample data; Staff for operational workflows.                                                                                             |
| Data               | Fictional data from onboarding sample data or `npm run seed:demo`.                                                                                                      |
| Clerk              | Development or demo Clerk account. Do not commit passwords or production user IDs.                                                                                      |
| Backend            | `VITE_API_BASE_URL` must point to the backend `/api`; backend `CLIENT_URL` must match frontend origin.                                                                  |
| Browser            | Start signed out for public/sign-up path; use a clean profile if possible.                                                                                              |
| Queue reorder data | Prepare at least two active queue entries for the same doctor and clinic date. The local seed has active queue entries, but not two active entries for the same doctor. |

## Deterministic Workflows

- seed data creation with configured local DB and Clerk IDs
- no-show risk scoring for a fixed appointment/patient history
- backend validation failures for invalid UUIDs/status values
- queue reorder validation when all active entries are supplied

## Workflows Requiring Seeded Or Created Data

- populated dashboard
- appointment booking
- queue reorder
- low/medium/high no-show risk examples

## Local Versus Production

| Topic       | Local                              | Production/release                                                    |
| ----------- | ---------------------------------- | --------------------------------------------------------------------- |
| URLs        | `localhost` defaults in setup docs | Not verified in repository                                            |
| Data        | Local seed is safe and fictional   | Must be verified as demo-safe before capture                          |
| Clerk       | Development keys and users         | Production keys and redirect URLs require owner setup                 |
| Database    | Local PostgreSQL/dev database      | Production migrations require owner-controlled `migrate deploy`       |
| Screenshots | Can be captured after app runs     | Must not be published as production evidence without URL/commit proof |
