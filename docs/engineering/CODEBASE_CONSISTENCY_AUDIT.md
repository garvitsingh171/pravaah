# Codebase Consistency Audit

This audit records the organization decisions made for the Pravaah refactor. It is based on source inspection of docs, package scripts, TypeScript configs, Vitest configs, backend modules, frontend features, shared test utilities, Playwright tests, Prisma files, and reserved packages.

## Fixed Now

| Area            | Finding                                                                                    | Evidence                                                                                                                                  | Severity | Change applied                                                               | Reason                                                                                                           | Remaining action                                                      | Suggested follow-up  |
| --------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------- |
| Backend tests   | Feature folders were crowded by colocated layer tests.                                     | `auth` had 8 tests beside production files; `appointments`, `clinics`, and `dashboard` each had 3-4 tests beside production files.        | Medium   | Moved backend module tests into feature-local `__tests__/` directories.      | Keeps tests discoverable without mixing production and test files.                                               | Run backend Vitest and type checks manually.                          | None if checks pass. |
| Backend imports | Moving tests changed relative path depth.                                                  | Tests imported same-module files via `./*.js`, sibling modules via `../<module>/*.js`, and shared config/generated/utils via `../../...`. | Medium   | Updated moved test imports and `vi.mock()` specifiers to the new depth.      | Preserves NodeNext `.js` specifiers and Vitest mock targets.                                                     | Run backend Vitest manually.                                          | None if checks pass. |
| Documentation   | The repo lacked an engineering organization guide for test placement and folder decisions. | Existing docs covered architecture, backend, frontend, and testing, but not a single code organization policy.                            | Medium   | Added `docs/engineering/CODE_ORGANIZATION.md`.                               | Gives contributors and interviewers one map for structure, layers, imports, fixtures, mocks, and anti-patterns.  | Keep this guide updated with future structural changes.               | None.                |

## Documented Intentional Exception

| Backend modules             | Not every module has every layer file.                                       | `health` has only route/controller; `predictions` has service/types/tests and no router/controller/repository. | Low      | Documented as intentional.                   | Consistency means responsibility alignment, not artificial symmetry.        | Keep small modules small.                                                              | Revisit only if public prediction routes or health logic grows.             |
| Backend validation          | `auth.validation.ts` reuses clinic creation validation.                      | `onboardingClinicSchema = createClinicSchema`.                                                                 | Low      | Left unchanged and documented as acceptable. | Prevents drift between onboarding clinic input and clinic validation rules. | Watch for divergence if standalone clinic creation changes later.                      | Split only if onboarding and clinic settings requirements diverge.          |
| Backend shared test helpers | Route-inspection helper remains feature-local.                               | Express router inspection appears only in `auth/__tests__/auth.routes.test.ts`.                                | Low      | No shared helper created.                    | A global helper would add indirection without reuse.                        | Extract to `apps/server/src/test/helpers` only if another module needs the same logic. | Add `expressRouteInspector.ts` when at least two route tests share it.      |
| Frontend tests              | Frontend tests remain colocated rather than using backend-style `__tests__`. | Page/component tests live beside pages/components; shared helpers are under `apps/web/src/test`.               | Low      | Documented as intentional.                   | Frontend ownership is clearer when tests sit near UI units.                 | Reconsider only when a feature folder becomes genuinely crowded.                       | Introduce a feature-local `tests/` folder only for large frontend features. |
| E2E structure               | Root E2E remains at root.                                                    | `playwright.config.ts` has `testDir: './e2e'` and starts both frontend and backend.                            | Low      | Left unchanged and documented.               | E2E tests span workspaces and external services.                            | Keep helpers under `e2e/helpers` and setup under `e2e/setup`.                          | Add `e2e/specs` only if spec count grows.                                   |
| Generated code              | Prisma generated output remains unmoved.                                     | Generator output is `apps/server/src/generated/prisma`.                                                        | Low      | Left unchanged.                              | Generated code should not be reorganized manually.                          | Do not edit generated files.                                                           | None.                                                                       |
| Reserved packages           | `packages/` stays reserved.                                                  | Only `packages/.gitkeep` exists.                                                                               | Low      | Left unchanged.                              | No stable shared package exists yet.                                        | Avoid creating placeholder shared packages.                                            | Create a package only for real cross-workspace code.                        |
